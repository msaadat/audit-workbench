The audit lifecycle

One agent run walks the whole engagement.

01 · INTAKE

Import the audit folder

Mixed local folders are compared with prior imports, staged, routed and loaded idempotently — tables and documents alike.

02 · PLAN

APM & RCM

An assistant interview captures context, then drafts the planning memorandum and the Risk & Control Matrix with planned tests.

03 · FIELDWORK

Execute the tests

RCM-linked Data Tests and Document Tests run locally, with durable results, exceptions and execution history.

04 · FINDINGS

Disposition observations

Execution observations are dispositioned; supported ones become editable IIA-style findings tied to evidence.

05 · REPORT

Draft & quality-check

An editable report is generated from live context, traceability-checked, and reconciled against auditor edits.

Two operating modes: auto mode applies validated changes; permission mode pauses at editable approval batches. Runs can be paused, resumed, steered and replayed — and mandatory output stages stay deterministic even if model expansion fails.

The architectural moat

Populations never leave the machine.

The configured model sees schemas, aggregate statistics, bounded row previews and attached document context — never a wholesale data dump. Tools execute locally on Polars; the orchestrator, not the model, decides whether a mutation applies.

Works with Groq, OpenRouter, Mistral, OpenCode Zen, Cerebras — or fully offline against a local LM Studio model.

Why it matters: useful agentic analysis with predictable context limits, and deterministic checks that model output can never overwrite.

Plan

The RCM is the spine of the engagement.

An assistant interview turns engagement context into an editable Audit Planning Memorandum and a Risk & Control Matrix: processes, risks, ratings, assertions, controls and planned tests.

Every downstream artifact — test executions, observations, evidence requests and working papers — hangs off its RCM row, so coverage is always visible.

Why it matters: planning isn't a document that goes stale; it's the live structure fieldwork rolls up into.

Fieldwork · data

Durable Data Tests, not throwaway queries.

Exploratory or RCM-linked tests run on three engines: a 15-test analytics library (Benford, duplicates, gaps, outliers, sampling and more), editable validation rules, and visible, AST-guarded Polars when a standard procedure isn't enough.

Runs keep bounded result and exception artifacts, histories, hashes and table fingerprints — so a conclusion can always be traced to the execution that produced it.

Fieldwork · documents

Documentary evidence, anchored and cited.

PDFs, DOCX, text and images are ingested with extraction previews and immutable typed evidence anchors. Ask cited questions; answers stay tied to source hashes and the exact included text.

Document Tests cover vouching and tracing, attribute testing, document and minutes review — with explainable exact, normalized, fuzzy, numeric-tolerance and date-tolerance comparisons, seeded samples and resumable per-item state.

Why it matters: model interpretation is presented separately and never replaces stored comparison evidence.

Output

From observation to defensible report.

Supported observations become editable IIA-style findings — condition, criteria, cause, effect, recommendation, management response — each carrying typed evidence links.

The report is generated from live planning-through-finding context, checked by advisory RCM → test → execution → evidence traceability, and regenerations reconcile side by side so auditor edits are never silently overwritten. Open material work yields a clearly labelled preliminary report, not an unsupported conclusion.

Command centre

A dashboard that knows what's next.

The dashboard surfaces the next best action, flags results that need attention, and curates four to six RCM-linked test results using deterministic risk, exception and relevance scoring. Tiles are live — they recompute when the data changes.

Agent runs are durable and steerable: pause, resume, cancel, steer mid-run, approve editable batches, replay the event history, and recover cleanly after a restart.

Why it matters: the auditor reviews and directs the engagement instead of babysitting a chat window.
