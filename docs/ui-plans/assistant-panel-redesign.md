# Assistant panel redesign: one thread, three widths

**Status:** design proposed on 5 September 2026, **built** (see "Order of
work"). This is the
evaluation the question asked for — can the Assistant tab go, leaving a
sidebar that expands to the whole screen — and the handoff for building it.
Every claim about what the code does today was read from the working tree at
commit `fec0f23`. The answer is yes, and the sections below say what the tab
provides that the sidebar does not, where each of those things goes, and
what is lost.

It uses the vocabulary of [`fieldwork-views-redesign.md`](fieldwork-views-redesign.md)
and [`sources-planning-reporting-redesign.md`](sources-planning-reporting-redesign.md):
tokens, list rows with a dot and a meta line, cards at `--aw-radius-control`,
one primary per header.

two details that are not.

## What exists today: two frames, one thread

The conversation is one component, `ConsoleThread.vue` (head, history,
transcript, composer), rendered in two frames:

- **The Assistant tab** is a route, `/workspace/:id/console`
  (`ConsoleView.vue`), reached from the header's `Record | Assistant`
  switcher. Three columns: a 16.5rem chat rail (`ChatHistoryPanel` docked), the
  thread at full width with the transcript centred at 46rem, and a 17rem right
  rail holding `EngagementState` (the three phases, their chips and
  disclosures) above `PlanSpine` (the active run's stages). Below 52rem of
  container the two rails become dialogs behind `Chats` and `Plan` buttons.
- **The sidebar** is `AgentDrawer.vue`, mounted by `WorkspaceView.vue` on
  every surface except the console. A layout column that pushes the page:
  416 px by default, resizable 340–680, capped so the page keeps 880 px.
  Collapsed it is a 3.25rem rail with one sparkle icon. Its head adds two
  actions to the thread's: `Plan`, which opens `PlanSpine` in a modal, and
  collapse. The chat list is a dropdown that overlays the transcript below
  the head.

Both read the same stores (`useAgentRun`, `useAssistantChat`); a run started
in one is live in the other. `useAgentRun` opens the drawer itself whenever a
run starts (`drawerOpen = true` in three places) and remembers the state per
workspace.

## What is wrong today

**Shared by both frames**

1. One conversation, two addresses. The header calls the assistant a *place*
   (a pill beside `Record`), and the drawer makes it a *state* of every other
   place. Pressing `Assistant` with the drawer open shows the same thread,
   wider, with different chrome: docked chats instead of a dropdown, a plan
   rail instead of a plan modal, a status rail nothing else has.
2. The transcript restates work. In the `Draft findings.` run the projection
   carries 22 consecutive `Reading the observation, the target RCM row, the
   test…` lines and, across the chat's four runs, five `Fieldwork complete —
   Completed all 0 scheduled tests` milestone cards. A milestone whose every
   metric is zero is a sentence, not a result; a reading line is activity,
   not conversation.
3. Milestone cards are sized for the console (17.6 px headline, a metrics
   `dl`, highlights, links). In the drawer one card is a screen.
4. The composer's toolbar (`Context`, `Auto ▾`, `Send`) and the thread head
   (sparkle, title, status tag, live dot, `+`, two more buttons) each hold
   more than the drawer's width reads at once.

**The Assistant tab**

5. Its right rail is the engagement record again. `Progress` (`Planning · 1
   of 3`, `32 RCM rows have no test`, the phase chips) is what the record page
   is for, and the record is one click away on the same header.
6. The plan rail is per run but sits beside the whole conversation; when the
   chat's latest run is finished it shows a finished plan under a live
   transcript.
7. On a narrow window both rails become modals, so the tab's only advantage
   over the drawer — width — is exactly what it loses first.

**The sidebar**

8. Collapsed, it costs 52 px on every page for one icon.
9. Open, it squeezes a two-pane page: on the findings register at 1440 px the
   detail toolbar wraps and `Save finding` becomes two lines.
10. `Plan` is a modal over a drawer; the chat list is an overlay over the
    transcript; rename is a dialog. Three layers for one column.

## Can the tab go?

Yes. Everything the tab provides is either already elsewhere or is a width,
and width is a property the sidebar can take.

| The tab provides | Where it goes |
|---|---|
| A wide transcript (46rem) | The **expanded** state: the panel takes the workspace below the header, thread at 760 px |
| The docked chat list | The expanded state's left column; docked, the title's menu |
| The plan rail | The expanded state's right column; docked, a one-line strip under the head while a run works, opening in place |
| The `Progress` rail | Nowhere in the panel. The engagement record is the index; the expanded state carries one card, `Where the engagement stands`, that links to it |
| A URL for the assistant | `?assistant=full` on any workspace route (docked: `?chat=<id>`). `/console` redirects to the record with `?assistant=full`, so every existing link lands |
| A place in the header switcher | The switcher goes. `Record` alone is not a switch, and the crumb bar already says `Engagement record`; the header gets an `Assistant` toggle in its right cluster |
| The mobile `Chats` / `Plan` dialogs | The expanded state *is* the narrow layout: under 1,320 px of window (where 440 px of panel would leave less than the 880 px page minimum) docked skips straight to expanded |

What is lost, stated plainly: the assistant is no longer a destination in the
same sense as the record. There is no page whose only content is the chat;
there is a page with the chat over it. A reviewer sent `?assistant=full` sees
the same thing they see today at `/console`, and pressing `⇥` or `Esc` finds
the page they were on underneath — which today's console cannot offer, since
leaving it is a navigation.

## The panel

One component, `AssistantPanel.vue`, mounted once by `WorkspaceView.vue` on
every workspace route. Its `mode` is workspace state in `useAgentRun`
(`panelMode: 'closed' | 'docked' | 'expanded'`, replacing `drawerOpen`),
persisted per workspace as the drawer's open state is today.

| State | Width | Triggered by | Leaves by |
|---|---|---|---|
| Closed | 0. Nothing mounted. | `✕`, or the header toggle while open | — |
| Docked | 440 px default, 360–720, resizable; pushes the page | The header toggle; a run starting (today's three `drawerOpen = true` sites); a milestone or record link with `?chat=`; `⇥` from expanded | `✕`; `⤢` |
| Expanded | The workspace area below the header, `position: absolute; inset: 0` over `.workspace-layout`; the page stays mounted | `⤢` in the panel head; `?assistant=full`; docked when the window is under 1,320 px | `⇥`; `Esc`; `✕` |

The header toggle (`Assistant`, sparkle, in the right cluster beside
`Import`) shows the panel's state: outlined when closed with a 7 px mint dot
when a run is live (amber when a run needs the auditor), filled `--aw-teal-600`
when open. It is the only trace of the assistant when closed — the collapsed
rail is removed.

### Docked (`AssistantDocked.dc.html`)

A column at `--aw-panel` with a left rule, three parts and a footer:

- **Head** (44 px): sparkle in `--aw-teal`, the chat title at 13 px 600 with a
  chevron — its menu is the chat list (today's `ChatHistoryPanel` as a
  popover, rows as below, `New chat` at the top, rename and delete on the
  row's kebab) — one status pill (`running` info, `needs you` warn, `failed`
  bad; none when idle), then `+`, `⤢`, `✕` as 28 px icon buttons. The live
  dot goes: the pill says the run is running, and `--aw-warn` on it says the
  connection dropped.
- **Plan strip** (36 px, `--aw-raised`, bottom rule), only while a run of this
  chat is working: spinner, the current stage at 12.5 px 600, `stage 5 of 5 ·
  2m 10s` in `--aw-muted`, and `Plan` as a chevron link that unfolds
  `PlanSpine` in place under the strip. No modal. Once the run settles the
  strip goes; the run receipt at the end of the transcript holds the plan
  behind `Units and errors`.
- **Transcript** at the panel's width, 14 px gaps, per the density rules
  below.
- **Composer** as today (`Context`, `Auto ▾`, `Stop` while a run is active,
  `Send`), placeholder `Send a message to steer the run…` while it is.

The page beside it is the page at the width it has: the findings register at
1,000 px drops its right cards under the narrative (the plan for that page
already calls for a single column under 34rem) and its review bar wraps.

### Expanded (`AssistantExpanded.dc.html`)

Grid `264px minmax(0,1fr) 320px` over the workspace area, each column
scrolling on its own.

- **Chats** (left, `--aw-panel`, right rule): `Chats` and `+` in a 44 px head,
  a search field, then list rows in the fieldwork form — 9 px dot in the last
  run's tone (`info` running, `warn` a run with failures, `ok` clean, neutral
  no run), title at 13 px, meta `running · 2 Sep 00:00 · 5 messages` or
  `1 Sep 23:05 · 10 messages · 3 runs with failures`. The active row takes
  `--aw-teal-soft` and the teal rule.
- **Thread** (centre): the same head as docked with `⇥` in place of `⤢`,
  padding 0 16 px 0 22 px; the transcript at 760 px max width centred, 16 px
  gaps, padding 20 px 24 px; the composer at the same 760 px.
- **Right column** (`--aw-raised`, left rule, padding 14 px), three cards:
  - **Where the engagement stands** (`1 of 3`): the three-segment phase arc
    (`--aw-info` in progress, `--aw-warn` attention, `--aw-ok` complete,
    `--aw-border-strong` not started), one sentence (`Planning · 32 RCM rows
    have no test. Fieldwork and the report need attention.`) and `Open the
    engagement record`. This is the whole of `EngagementState` the panel
    keeps: the phase chips, disclosures and actions stay on the record.
  - **Plan · Draft findings** (`5 stages`): one row per stage — check in
    `--aw-ok` done, spinner running, 8 px neutral dot queued — the stage name
    and a right-aligned note (`reused`, `0 to run`, `24 rows · 3s`, `9 of 24
    · 2m 10s`), then `Units and errors` as a chevron link opening today's
    unit rows. `PlanSpine` re-cut into a card; its stage logic is unchanged.
  - **Read for this run** (`at 00:00`): the run's context projection — one
    sentence for the supporting sources, one row per document (file icon,
    name, category), `3 more documents`, and the withheld line in
    `--aw-warn-ink`. Today's `AgentContextCard`, moved out of the transcript
    for the run in flight; it stays in the transcript as a compact line once
    the run has finished.

### Transcript density (both states)

- **User turn**: `--aw-teal` bubble, white 13 px text, 12 px radius with a
  3 px corner toward the margin, the time under it in `--aw-muted` 11 px,
  right-aligned at 78 % max width.
- **Assistant line**: plain 13 px / 1.5 `--aw-ink`, no bubble, 92 % max
  width.
- **Milestone card**: a 22 px status square (`--aw-ok-soft` check, or
  `--aw-warn-soft` triangle for `completed_with_issues`), headline 13.5 px
  600, summary 12.5 px `--aw-ink-soft`, metrics as one `label value` row at
  11.5 px (value 600), highlights as rows with a 7 px `--aw-danger` dot, a
  12.5 px `--aw-danger-ink` label and an 11.5 px detail, and the artifact
  link as a teal reference chip. A milestone whose metrics are all zero and
  whose highlights are empty renders as an assistant line (`Fieldwork: nothing
  scheduled to run.`), not a card.
- **Activity lines** (`Reading …`, `Still drafting …`, `The first draft didn't
  match the required shape …`) are not transcript entries while the run works;
  they are the working block's history. Consecutive activity lines collapse
  to the working block: spinner, the stage as a 13 px 600 label, `9 of 24 ·
  2m 10s · taking a while` in `--aw-muted`, and the progress checklist
  (`--aw-ok` checks for done items, a spinner on the current one). Once the
  run settles they fold into the receipt behind `N steps`.
- **Run receipt**: `--aw-canvas` card, 20 px icon square, title 12 px, subline
  `Done · 25/25 · 5m 42s` in mono-tabular `--aw-muted`, the narration lines
  under it at 11.5 px (two shown, `N more` chevron). `--aw-danger-line` border
  and a warning icon when failed; the `Continue` / `Retry` controls as today.
- Interaction and approval cards keep their current layout; they are the
  transcript's forms and are already compact.

## Header and routing

- `WorkspaceView.vue`: the `surface-switcher` nav is removed; the `Assistant`
  toggle joins the right cluster; `AssistantPanel` replaces `AgentDrawer` and
  mounts on every route. `.workspace-layout` gets `position: relative` (it
  has it) and the expanded panel overlays it.
- `router.ts`: `console` becomes a redirect to the workspace root with
  `assistant=full`; `ConsoleView.vue` is deleted. `App.vue`'s
  `WORKSPACE_ROUTES` drops `workspace-console`.
- `useWorkspaceNavigation.ts`: the `console` destination stays as a key (the
  backend's navigation targets and `routeForTarget`'s fallback name it) but
  resolves to `{ surface: 'home', section: '', keys: ['chat', 'assistant'] }`
  with `assistant: 'full'` applied; every other destination gains the two
  keys `chat` and `assistant` in `ownedQuery`, so a deep link into a page can
  carry the panel state. `WorkspaceView` reads them on route change and sets
  `panelMode` and the active chat; it strips them once applied so the page's
  own history entries stay clean.
- `useAgentRun.ts`: `drawerOpen` → `panelMode`; the three `drawerOpen = true`
  sites set `docked` unless the mode is already `expanded`; `toggleDrawer` →
  `togglePanel` (closed ⇄ last open mode); `savedPanelState` keeps the last
  open mode as well as whether it was open. `Esc` in the expanded panel goes
  to docked; `Esc` in docked does nothing (the composer owns the key).
- Below 1,320 px of window (`440 + 880`) a request for `docked` yields
  `expanded`; the drawer's `MIN_CONTENT_WIDTH` becomes this rule.

## Backend and data

- **Chat summaries** need the last run's state. `GET /assistant/chats` returns
  `title`, `updated_at`, `message_count` today; the list row's dot and meta
  (`running`, `3 runs with failures`) need `last_run_status` and a count of
  runs whose status is `failed` or `completed_with_failures`. Both are on the
  chat record already; the summary just does not carry them.
- **Navigation targets**: the backend names `console` as a target in
  milestones and suggestions. Nothing changes server-side; the frontend maps
  it as above. A later cleanup can rename the target `assistant`.
- Nothing else. The plan, the context projection, the phases and the run
  projections are all payloads the two frames already read.

## Order of work

All five steps are done.

1. **`AssistantPanel` replaces `AgentDrawer`.** `agent/AssistantPanel.vue` owns
   the frame — mode, width, resize, the expanded grid. `useAgentRun`'s
   `drawerOpen` boolean became `panelMode: 'closed' | 'docked' | 'expanded'`
   with `openPanel`, `togglePanel` and `setPanelMode`; the three auto-open
   sites and the twenty-odd `if (!drawerOpen) toggleDrawer()` call sites all
   collapse to `openPanel()`. `affordableMode` answers a request to dock with
   expansion below 1,320 px of window. The collapsed rail is gone and the
   header carries an `Assistant` toggle with a live dot instead.
2. **Transcript density.** A milestone whose metrics are all zero and whose
   highlights are empty renders as one line (`Fieldwork: nothing to report.`)
   rather than a card — five of them appeared across one chat's four runs. The
   thread head lost the live dot; the status pill carries the connection state
   in `--aw-warn` instead, and the title renames in place.
3. **Expanded mode.** `agent/ChatList.vue` draws the rows with a dot in the
   last run's tone and the meta line the summaries now carry;
   `agent/PlanStrip.vue` is the docked live strip that unfolds `PlanSpine` in
   place (no modal); `PlanSpine` gained a `card` presentation and
   `EngagementState` a `compact` one — the arc, one sentence, and a link to the
   record.
4. **Routing.** `/console` redirects to the workspace root with
   `?assistant=full`; `WorkspaceView` applies `assistant` and `chat` from the
   query and strips them; the `console` destination resolves to the record with
   those two keys; the header switcher, `ConsoleView.vue`, `AgentDrawer.vue`
   and `ChatHistoryPanel.vue` are deleted, and `console` is no longer a
   `WorkspaceSurface`.
5. **Chat summaries** carry `last_run_status`, `failed_run_count` and
   `run_count`, grouped from the run records in one pass per page.

What is not built from this plan: the run receipt's and milestone card's exact
type sizes, and the `Read for this run` rail card — the context projection
still renders in the transcript rather than being lifted out of it for the run
in flight.

## What the mockups assume

- The working block's checklist shows three finding titles as progress
  items. The run's `progress` projection is what `AgentThinking` renders
  today; the titles are drawn from the run's later milestone, since the
  projection itself was not captured mid-run.
- The chat rows' `running` and `3 runs with failures` come from the chat
  records, not from the summaries endpoint, which does not carry them yet
  (see "Backend and data").
- Everything else — the messages, the milestone and its highlights, the
  stages and their counts, the documents read and the one held back — is the
  `Draft findings.` run's own projection.
